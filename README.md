# 寶可夢 GO 去留指南（Keep or Transfer）

把《Pokémon GO》裡 1700 多個實裝型態（目前 1718 個：區域形態、超級進化、暗影、極巨化⋯）一次列齊，
告訴你**哪些值得留下、哪些可以直接傳送**，還能輸入自己那隻的 IV 算對戰排名。

## 🌐 直接線上使用

**https://xiangwang2000.github.io/pokemon-go-keep-or-release/**

不用安裝任何東西，手機或電腦的瀏覽器打開就能查。想留在本機跑也可以：

```powershell
python -m http.server 8600 --directory site
# 然後開 http://localhost:8600/
```

## 怎麼用

1. **找哪隻**：搜尋框輸入中文／英文名或編號；也可以用屬性、評級、類別（傳說／幻獸／異獸、暗影、極巨化⋯）、世代下拉篩選。篩選、排序與搜尋會存在自己的瀏覽器裡，誤關分頁回來不用重設。
2. **看評級**：每張卡片右上是四級判定——必留／建議保留／看情況／可傳送；卡片**右上角**的彩底角章是你的標記、**左上角**徽章是形態資訊（極＝可參加極巨戰／G·巨＝可參加超極巨化戰／超＝有超級進化形態）。點卡片看完整理由（PvP 排名、限制盃榜、PvE 估算、極巨戰估算、推薦帶法），並附「**接下來該做什麼**」動作指引。暗影個體另外附**淨化建議**（要不要直接淨化、幾級條件可淨百）。卡片底下的小字是**各衡量尺度並列**（CP · PvP 名次 · PvE 百分位 · Max 百分位），存在才顯示，不是「適合哪邊」的意思。
3. **算 IV**：詳細頁最下方有計算機，填入那隻的攻／防／血，會回報各聯賽的 IV 排名與最佳等級；暗影個體會連帶顯示**淨化後 IV**（淨百就會直接喊出來）。
4. **標記收藏**：詳情頁的「標記這隻」按鈕可在保留／可送／已送之間循環，方便清理前清點——記錄存在自己的瀏覽器裡（只到型態粒度）；換裝置或清瀏覽資料前，可用同一頁的「**備份我的標記／匯入備份**」把記錄存成 JSON 檔帶走。
5. **清理前最後防線**：把名單複製成遊戲收藏搜尋字串時，若名單裡同編號混有暗影／極巨化／一般個體，站上會**跳窗警告「不得用編號全選傳送」**（遊戲搜尋會一次選中同編號全部形態）；全暗影／全可極巨化的名單會自動補 `&shadow`／`&dynamax` 限定詞。

## 名詞槽位：兩份 500 名次不一樣

- **500 格式總榜**：PvPoke 的 500 CP 格式**總排名**（固定公式、歷代榜單累積），卡片上的「500 格式總榜 #N」是它。
- **小小盃**：現行季節的 500 CP 活動賽制**杯規榜**，列在詳細頁「限制盃／特殊盃賽排名」。
- 兩份榜名次可能差很多，站上已分開命名——看到「小小盃」字樣一律指現行杯規榜。

## 評級怎麼判

判定**主依據只看主力聯盟（超級 1500／高級 2500／大師 10000）**；小小盃（500 CP 活動賽制）不灌入主依據，只在該盃規榜前 50 名時當「限制盃人選」建議保留＋次級註記：

| 條件 | 評級 |
|--------------------------|----------------|
| 幻獸 / 無極汰那 / 超極巨化 / 超級進化 / 主力聯盟前 50 名 / PvE 估算前 3% / PvE 屬性分榜前 3% | 必留 |
| 已暗影且主力聯盟前 200 / 傳說 / 異獸 / 主力聯盟前 150 / PvE 前 10% / 現行杯規榜前 50 名（含小小盃） / 極巨戰攻手估算前 10% | 建議保留 |
| PvE 屬性分榜前 10%（單屬性絕活，不參與「可傳送」判定） / 區域限定 / 未完全進化 / 同進化線下游皆可送（自身戰力夠硬的進化前型態不降） / 主力聯盟前 350 | 看情況 |
| 其餘（附圖鑑例外說明） | 可傳送 |

暗影個體另有保護：全物種 PvE 前 10% 或任一屬性分榜前 10% 的暗影**不會被判可傳送**（火箭隊輪替，暗影再取得不易）。

Max Battle 只有極巨化個體能出戰，所以可極巨化型態另有一套攻手估算（極巨攻擊 DPS），不跟普通 PvE 混著比——
極巨攻擊屬性＝**快招屬性**（超極巨化個體則是專屬招式、屬性固定）；威力計入分級（一般 250/300/350、
超極巨 350/400/450，Max+ 再 +100——估算取最高級尺度、詳細頁揭露假設）。極巨化清單源自 pokemondb，另以 `MAX_EXTRA`／`MAX_SPECIAL`
補標清單漏列的特例（美錄梅塔經 Max Battle 特殊調查取得；無極汰那為 GO Pass 限定的單次取得、專屬招式 Dynamax Cannon）。完整規則見[開發說明](docs/DEVELOPMENT.md)。

## 資料與免責

- 數值來自開源社群資料：[PvPoke](https://pvpoke.com)（型態、排行榜）、[PokeMiners GameMaster](https://github.com/PokeMiners/game_masters)（PvE 數值、進化方向、極巨招式屬性）、[pokemondb](https://pokemondb.net/go/dynamax-attackers)（極巨化清單）、[WatWowMap](https://github.com/WatWowMap)（型態圖示）等，完整致謝見[開發說明](docs/DEVELOPMENT.md)。
- PvE 強度為估算值、盃賽 meta 隨季輪替（榜單標明撈取日期）；極巨戰估算以「威力分級尺度＋可解釋的集條假設」給相對排名，不是精算模擬（假設已在詳細頁揭露）；判斷以攻略建議為性質，非官方資料。

## 本 repo 的結構

```
site/   網站本體（GitHub Pages 上線的是這個資料夾）；js/core.js＝核心計算（Node 建置與瀏覽器共用同一份）
data/   建置用原始資料（PvPoke、PokeMiners、uicons 等來源快取）
tools/  資料抓取與建置腳本；tools/archive/ 是研究階段的一次性探查工具
docs/   開發者文件（資料更新流程、判定規則細節、審查處置表、升降級報告）
```

## 幫它活著

資料來源會隨 GO 改版而舊（例如盃賽榜、Ja 新寶可夢）。如果你發現哪隻的評級怪怪的、
或最近實裝到 GO 的新寶可夢還沒出現在站上，歡迎開 issue 回報。

想自己跑建置、研究判定規則、或者修正資料？開發流程都整理在[docs/DEVELOPMENT.md](docs/DEVELOPMENT.md)——
幾個 node 指令就會跑完抓取、建置、稽核三步。
